Overview

The task: classify which accident is unfolding in a nuclear power plant from the first W seconds of sensor data after onset (t0), across 12 accident classes (LOCA, LOCAC, SLBIC, SLBOC, SGATR, SGBTR, RW, RI, FLB, MD, LR, LLB). Run-level split (seed 2026): 725 train / 242 validation / 244 test runs. Two instrument settings: all 96 variables, and realistic 88 — the 96 minus 8 oracle channels (WLR, HLW, WBK, MBK, EBK, WTRA, WTRB, WFLB) that measure the accident itself and would not exist on a real plant. Windows W ∈ {30, 60, 120, 300, 600} s at onsets t0 ∈ {20, 100} s.

Model lineup: LogReg, LogReg+, Random Forest, CNN, GRU (homework core) and MultiRocket+HYDRA, Rocket, MiniRocket (advanced extensions, same splits and protocol).

Headline — test macro-F1 at t0 = 100 s, realistic channels

At the Task E submission protocol (t0 = 20 s, W = 60 s) every model sits at the information ceiling of that window — macro-F1 0.1892 — because at that onset the first 60 s of realistic channels do not yet separate the classes. The official submission file, pred_E_W60_test.csv, stacks all 8 models' predictions at this protocol (see Live verification below).

Train — look up a measured configuration

Pick a configuration and hit Train. The panel walks through the study pipeline and then reveals the real measured result for exactly that configuration (same splits, seed 2026 protocol). If a configuration was never measured, it says so — nothing is interpolated.

  • Load data — NPPAD run windows from S3 dataset
  • Featurize — window channels (t0, W, variable set)
  • Fit — train on 725 runs, select on 242 validation runs
  • Evaluate — score the 244 held-out test runs

Run all code — retrain in your browser, rebuild the official file

Hit Run all code and this page trains the three classical models for real, in your browser: LogReg, LogReg+ and Random Forest are fitted live with scikit-learn running in WebAssembly (Pyodide) on the study's own W = 60 s summary features, using the exact study protocol (same splits, seed 2026). The other five models (CNN, GRU, MultiRocket+HYDRA, Rocket, MiniRocket) are recomputed from the study's shipped prediction files — their training needs the full time-series pipelines and lives in the notebook and the cloud runner below. Every row is labeled with how it was obtained; the two are never blurred.

When the run finishes, the page assembles a new official submission file — pred_E_W60_test.csv, all 8 model blocks × 244 test rows — from the fresh browser-trained predictions (classical models) and the shipped rows verbatim (the other five), verifies every block in the page, and offers it as a download.

Scope, stated plainly: the classical models retrain in your browser; the deep and rocket models recompute from the shipped study predictions; full retraining of all models runs in the notebook (or the cloud runner). The generated file downloads to your device — this page holds no AWS credentials and cannot write to S3 itself. The first run downloads the Pyodide + scikit-learn runtime and the feature file (2.6 MB); training itself takes seconds to under a minute on a desktop.

  • Load the Python runtime (Pyodide + scikit-learn) and the W = 60 s feature file
  • Train LogReg (raw summary features)
  • Train LogReg+ (log-compressed features, C selected on validation)
  • Train Random Forest (400 trees, seed 2026)
  • Recompute CNN, GRU, MultiRocket+HYDRA, Rocket, MiniRocket from the shipped files
  • Assemble + verify the new official file (8 blocks × 244 rows)

Cloud training — retrain all models in the cloud

One click dispatches a GitHub Actions workflow that trains all 8 models for real at the official Task E protocol (t0 = 20 s, W = 60 s, realistic 88 channels) from the public S3 dataset, then publishes a fresh pred_E_W60_test.csv, results.json and status.json to the study bucket. This panel polls that status while a run is live and shows the cloud results when it finishes.

Activation pending: the dispatch call needs a fine-grained GitHub token scoped to the hydrotwin-site repo (Actions: read and write only), supplied by the site owner through a secure capture page — it is never stored in this page's source. Until it is supplied, the button stays inert; runs can still be dispatched from the repo's Actions tab, and this panel will show them here.
